# Implementation Plan: Base de datos PostgreSQL

**Branch**: `016-postgresql` | **Date**: 2026-11-09 | **Spec**: [spec.md](spec.md)

## Summary

La API pasó de SQLite a **PostgreSQL 17**, en el nuevo servicio `db` de Compose, sin cambiar su contrato HTTP. En el primer arranque importó sola la base SQLite del volumen `datos`: 16 de 16 filas, comprobadas tabla por tabla. El archivo `yaguachi.db` queda intacto como respaldo.

## Technical Context

**Dependencias**: `psycopg[binary]==3.3.8` y `psycopg-pool==3.3.3`.

**Conexión**:
- `DATABASE_URL` en Compose: `postgresql://yaguachi:${POSTGRES_PASSWORD}@db:5432/yaguachi`.
- La clave va en hexadecimal, porque viaja dentro de la URL.
- El pool tiene 20 conexiones por defecto (`YAGUACHI_DB_POOL`).
- Al arrancar se reintenta la conexión con espera creciente durante unos 60 s.

**Esquema**:
- Está en `api/esquema.py`, con migraciones versionadas (`meta.esquema_version`) que se aplican bajo un advisory lock.
- **Tipos:**
  - Las fechas siguen como TEXT ISO, con `COLLATE "C"` para que se ordenen igual que en SQLite.
  - Los REAL pasan a `DOUBLE PRECISION`.
  - Los ids son `GENERATED BY DEFAULT AS IDENTITY`.
  - Se agregaron índices para las consultas de los límites.

**Atomicidad**: `db_escritura()` toma `_db_lock` (el candado del proceso) y, dentro de la transacción, `pg_advisory_xact_lock`. Así los límites siguen siendo atómicos aun con varias réplicas o con un comando de consola en paralelo. `api/tests/test_atomicidad.py` falla si se quitan los candados.

**Importador**: `api/importar_sqlite.py` abre el SQLite en solo lectura.
- Se ejecuta solo si la base está vacía y existe `/app/datos/yaguachi.db`.
- También se puede lanzar a mano con `--importar-sqlite RUTA [--forzar]`.
- Hace todo en una transacción, conserva los ids, reajusta las secuencias (`setval`) y deja constancia en `meta.importado_sqlite`.
- Si falla, la API se detiene con un mensaje claro y PostgreSQL queda sin cambios.

## Pruebas de la API

Usan un PostgreSQL de pruebas aparte, nunca el de la app:

```bash
docker run -d --rm --name yw-pg-pruebas -e POSTGRES_PASSWORD=pruebas -e POSTGRES_USER=yaguachi \
  -e POSTGRES_DB=yaguachi_pruebas -p 127.0.0.1:55432:5432 postgres:17-alpine
pip install -r api/requirements.txt
python -m unittest discover api/tests        # crea y borra una base yaguachi_pruebas_<azar> por corrida
docker stop yw-pg-pruebas
```

Variables: `YAGUACHI_PRUEBAS_DB` (la URL de esa base) y `YAGUACHI_PRUEBAS_PUERTO` (el puerto de la API de pruebas, 8097 por defecto).

Resultado: **75 pruebas OK**, las 64 de antes más 9 del importador y 2 de atomicidad.

## Copia de seguridad

```bash
docker compose exec db pg_dump -U yaguachi yaguachi > respaldo.sql
# restaurar en una base vacía:
docker compose exec -T db psql -U yaguachi yaguachi < respaldo.sql
```
